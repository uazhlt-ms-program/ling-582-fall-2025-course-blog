## Task summary

_See [the rubric](https://parsertongue.org/courses/snlp-2/assignments/rubrics/class-competition/final/#task-summary)_

The goal of this task is to see if two texts are by the same or different authors. This task has been studied in depth in linguistics, it even has it's own field Stylometry. For this Kaggle competition, we were given a train dataset and a test dataset in the form of CSV files. The train dataset with 1,601 entries was manually labeled if the text in each entry (a combination of two snippets from either the same or different authors) with a 1 or 0 (more on this later). The test set was unlabeled and was what we were supposed to run our model on for inference.

While Stylometry can be computerized (ie doing feature engineering based on length of sentences, punctuation, etc) I wanted to know if a Sequence classifer pre-trained model could make the process more efficient.

There has been some research in the use of LLMs to identify authors, while this is a different task then the one I'm partaking in, I think it is notable to discuss (Huan & Chen, 2024). Huan and Chen specifically mention *why* something like a pretrained model (which I am using), isn't the best choice. The main reason to use LLMs instead of something like a BERT transformer is because for a transformer you need a lot of data -- which as you will see in my analysis, the lack of balanced data for this task reflects in the results. The reasons they say LLMs are good is because they have the reasoning to make linguistic conclusions, versus a pre-trained model's hidden feature engineerings. However, I am hesitant to believe Huan and Chen's claim based on something I did for this assignment.

I'll discuss later about the imabalance in the data, so I tried to ask JanAI using this prompt
```I want more data for a project I’m doing. The project is to tell if two text snippets are by the same author or a different author. 0 is for different author and 1 is for same author.
Right now my train data looks like this:
ID,TEXT,LABEL
0,"When his speaker remained silent Dirrul .... [I inputted more examples but leaving it at that]
the two texts are a single string seperated by [SNIPPET]
Create a new csv file with more training data with various authors``` 
When it spit back text, I asked it to tell me what the two authors are because I recognized some quotes from literature but not others. I tried to verify the authors and text it gave me, but to no avail. So, it seems it isn't that efficient at generating text by different authors that are factual - so can it do the reverse?
Who knows? One day I'll experiment, but for now we're doing old fashioned model.
In Huan and Chen's article they provided a result table that reflected Tf-IDF (which I used as my base), BERT (which I used for my main model), and GPT. Interestingly, their results comparing TF-IDF and BERT on the task of author identification resembled my proportions used for my same author task (around a 35% improvement from TF-IDF to BERT).





## Exploratory data analysis

_See [the rubric](https://parsertongue.org/courses/snlp-2/assignments/rubrics/class-competition/final/#exploratory-data-analysis)_
The data was an ID, TEXT (which were actually two texts by the same or different author combined with the string [SNIPPET]) and LABEL of 0 or 1 depending on if the texts were the same or different author.
To discover the dispersal of data, I checked several things. First the labels.
In the full dataset:

| **Dataset**        | **Entries** | **Label 0** | **Label 1** |
|----------------|---------|---------|---------|

| Train Dataset  | 1,280   | 999     | 281     |

I thought the data was imbalanced because the majority of entries being not the same author. I had a theory that the model would have a lower recall because it will learn more from not the same author as same. 
Hence, tried adding more data through augmentation with AI, but it made up things. 
So next I did research on other datasets and found this dataset on Kaggle [Spooky Authorship Dataset](https://www.kaggle.com/competitions/spooky-author-identification/data?select=train.zip)
It had text samples from three different authors with columns: ID, text, author.
While I didn't care about who the author was, I set something up that randomly selected two rows and put the two text columns together with [SNIPPET] and if the author was the same, set the corrosponding label.
While I ended up not using the data because it actually made my model worse, even though it balanced the two categories, here was the breakdown

## Approach

_See [the rubric](https://parsertongue.org/courses/snlp-2/assignments/rubrics/class-competition/final/#approach)_
My approach was to use a text classifier BERT model to classify the texts. 
1. Performed exploratory analysis and decided to add two new columns for each of the text snippets. This is also where I attempted to supplement with more data.
2. Seperated the dataframe into train, validation, and test and imported it into a Dataset for easier manipulation
3. Set up the tokenizer, I used bert-base-uncased as that was suggested by [Text classifier](https://huggingface.co/docs/transformers/en/tasks/sequence_classification) Though, I didn't just choose a Sequence classifier model because that post told me to. As I've learned in classes, Sequence models are great for NLP because they can take a sequence of words and learn features from it by transforming it into chunks of numerical representation. With these features, it can build dependencies which is useful in this task because you want to learn patterns and similarity of authors.

- For this I mapped the dataset and did some alterations for the model to better understand, such as renaming 'LABEL' and ignoring the actual texts columns and focusing on the IDs, input_ids, token_type_ids, attention_mask, and labels.
- Next I put it in the format of torch based on this example [Dealing with tokenizer](https://huggingface.co/docs/datasets/en/process)


4. Next I set up a data_collator with dynamic padding to better organize padding
5. Creating a metric to test the success of the model using accuracy, function taken from [Text Classifier](https://huggingface.co/docs/transformers/en/tasks/sequence_classification) along with other functions taken from class lectures that talked about evaluating binary classification models. 
6. Set up the training arguments as suggested by [Text Classifier](https://huggingface.co/docs/transformers/en/tasks/sequence_classification). My initial run was 3 num epochs, but I thought if I ran it longer it would be better - but that was not the case. I was *trying* to be novel and try new things, but HuggingFace knows what it is talking about. But at least I learned what didn't work as well (though all my experimentations did help me learn more about my model, and were relatively close to eachother ie 65%-67% compared to the top first model which was 70%) In the end I went with 5 epochs.

## Results
_See [the rubric](https://parsertongue.org/courses/snlp-2/assignments/rubrics/class-competition/final/#results)_


| **Metric**                 | **Baseline** | **New Model** | **Delta (New − Base)** |
| -------------------------- | ------------ | ------------- | ---------------------- |
| **Accuracy**               | 0.781       | 0.844         | **+0.064**            |
| **Precision**              | 0.500       | 0.875         | **+0.375**            |
| **Recall**                 | 0.085      | 0.378         | **+0.293**            |
| **F1 Score**               | 0.146       | 0.520          | **+0.374**            |
| **AUC ROC**                | —            | 0.727         | —                      |
| **Average Precision (AP)** | —            | 0.600          | —                      |

First, I set up a base model which used a similarity score and threshold to predict the label based on turning each text into a TFIDF vector. For this I took the training data used later for the model.


While accuracy is relatively high, compared to the Sequence model, it tends to dramatically mislabel the positive (same author) class as negative (not same author). More specifically, out of all the golden class 1 labels, it only gets 8% correct. This is a major issue.
The reason accuracy might be so high is because how much the data is imbalanced for negative.

For my model, I saved on best accuracy, which was epoch 3, though in retrospect, I should have tested with the model with the best Precission and recall.


Looking at the 'New Model' column there is a high accuracy, which can be misleading because as I predicted in the begining, the data heavily favors the negative class. 

The high precision means the predicted positives are truly positive. However, on the flip side recall is very low as it only accuratly predicts actual positives 38% of the time (so even though it out of the positives predicted, a high percentage are actually positive, it only picks positive in a third of the cases there are positives.)  The F1 score shows more of the imalance.

That is why I decided to also do the  Area Under the ROC and especially the AP.
The ROC AUC says it does an average job seperating positives and negatives. But because the data is imbalanced, I wanted to look more at AUC PR which is when the positive cases are ranked above negative The 60% means it is more than random, which is good, which suggests the reason the recall is so low is not because the model can't predict positives, but because the threshold is too high.

All that said, the delta shows there is a 35% average improvement in Precision, Recall, and F1 score, which is good. This shows there is an improvment in using a transformer based model compared to a normal vectorization model. However, it does follow the same proportional trend of high precision and low recall (though to more extremes.) This suggests even though the model improves matters, there is something to be said about the imbalance of the data (though again, when I tried to add data it did worse.)

## Future Improvements

_Describe how you might best improve your approach_

The first thing I'd do is balance out the data by augmenting more data. I think when I tried to add more data from the Kaggle dataset I mentioned, I added too much so it didn't actually represent what the test data would look like. It was 65% when submitting the prediction (although at the time I added the data, I wasn't checking the Precision, Recall or F1 score to tell.) I would go back and redo adding the data and try again, because I hadn't persued it after it got my lowest results.
If that still didn't work (or even along with that), I'd do a method like SMOTE (Synthetic Minority Over-sampling Technique) to better represent the minority by creating synthetic data in similar word vector spaces as data annotated as positive class.
